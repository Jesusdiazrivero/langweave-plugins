# Language mode

This file is the stable half of langweave's contract, and only that half. Everything tuned per
release — the replacement ceiling, how many new words a reply may introduce, which words are
known — arrives inside the profile the server returns, never from here. An old copy of this file
is still a correct one.

## This skill needs the langweave MCP server

Its tools come from langweave's hosted MCP server at `https://api.langweave.tech/mcp`. If they are not there,
say so in one sentence and then reply normally in the user's own language. Do not guess at
target-language words, and do not narrate what the skill would have done.

A user who has not chosen a target language yet gets a not-enrolled message from every tool. That
is not an error to work around: it is an account decision, made once at https://app.langweave.tech, and until
they make it there is nothing to weave. Point them there and carry on in their own language.

## The contract

langweave tracks how much of a target language this user can read. It exists so your replies can be
written partly in that language — individual words at first, whole sentences as their vocabulary
grows.

Every conversation, without being asked:

1. Before your first substantive reply, call `get_language_profile`. Pass `topic_hint` when the
   conversation has an obvious subject.
2. Weave every later reply according to that profile. Its numbers are limits, not suggestions:
   never exceed the replacement ceiling or the introductions-per-reply cap, gloss LEARNING words on
   first use, leave KNOWN words unglossed — a parenthesis showing a word's reading is not a gloss:
   keep it where the profile shows one, and add none where it does not — and never use a
   target-language word the profile does not list.

If `log_exposures` is among your tools:

3. After any reply that wove something, call `log_exposures` — one item per target-language word
   you used: `exposed_bare` when unglossed, `exposed_glossed` when glossed, `used_in_sentence` when
   it sat inside a fully translated sentence. This is the only thing that makes the user's
   vocabulary grow; skipping it freezes their progress silently.
4. If the user asks what a word means, log `user_asked_meaning` for it; if they ask how to read or
   pronounce it — not what it means — log `user_asked_reading` instead. When the question is both,
   or you are unsure, log `user_asked_meaning`. Either outweighs any number of exposures. If they
   say they know a word, or want it back in learning, call `update_item`.
5. Re-fetch the profile only when a tool result says it changed, when the user marks items, or when
   the topic shifts enough to warrant a new `topic_hint`. It does not go stale on its own.

If `log_exposures` is not among your tools, this account is on the Free plan: weave from the
profile, never use a word it does not list, and log nothing — there is nothing to log with.

Unsure about one specific word? `check_words`, where you have it, is the cheap lookup. The failure
mode that matters is unreadable half-translated text, not a missed opportunity: when in doubt, weave
less.
